# Athena Action/Observation Protocol v3

[English](#wire-contract) | [简体中文](#中文说明)

Athena desktop devices connect to the Runtime Client control plane through an outbound WebSocket. The protocol identifier is `athena.agent.v3`; reasoning remains on the Agent side while devices only execute typed capabilities and report observed state.

The protocol follows a strict layer split:

- **Decision Layer** produces the next typed Action.
- **Action Layer** executes the Action on the device.
- **Perception Layer** observes the resulting world state and emits the terminal Observation.

Browser Runtime, Desktop Runtime, File Runtime, and Terminal Runtime are execution adapters. Browser Observation, Desktop Observation, File Observation, Terminal Observation, Vision Observation, and Audio Observation engines are perception adapters.

## Wire Contract

- WebSocket endpoint: `GET /v1/control/device`
- Authentication: `Authorization: Bearer <control.device_token>`
- Encoding: one UTF-8 JSON object per WebSocket message
- Time: RFC 3339 UTC
- Correlation: `task_id + action_id + sequence`
- Delivery: at least once; devices deduplicate with `idempotency_key`
- Cancellation: the server sends `CANCEL` when the caller disconnects or the deadline expires
- Stream correlation: streaming endpoints return `X-Athena-Task-ID`; closing that presentation stream does not cancel the task

### Connection

The first device message must be `HELLO`. The server responds with `WELCOME`; either side may then send heartbeat messages.

```json
{
  "protocol": "athena.agent.v3",
  "type": "HELLO",
  "device_id": "device-01",
  "name": "Athena Desktop",
  "platform": "darwin",
  "architecture": "arm64",
  "capabilities": ["browser.open", "browser.navigate", "browser.observe", "browser.click", "browser.type", "browser.press", "browser.scroll", "app.open"],
  "sent_at": "2026-08-03T10:00:00Z"
}
```

### Action

```json
{
  "protocol": "athena.agent.v3",
  "type": "ACTION",
  "task_id": "task-01",
  "action_id": "action-01",
  "session_id": "athena-00000000000000000000000000000000",
  "sequence": 1,
  "idempotency_key": "task-01:action-01",
  "deadline": "2026-08-03T10:00:30Z",
  "capability": "browser.open",
  "arguments": {"url": "https://www.youtube.com"},
  "policy": {"risk": "LOW", "decision": "ALLOW"}
}
```

The Runtime Client rejects actions whose capability was not advertised by the selected device. `policy.decision` is `ALLOW`, `ASK_USER`, or `BLOCK`.

### Observation

```json
{
  "protocol": "athena.agent.v3",
  "type": "OBSERVATION",
  "task_id": "task-01",
  "action_id": "action-01",
  "session_id": "athena-00000000000000000000000000000000",
  "sequence": 1,
  "status": "SUCCEEDED",
  "observed_at": "2026-08-03T10:00:04Z",
  "state": {
    "url": "https://www.youtube.com",
    "title": "YouTube",
    "page": {"url": "https://www.youtube.com", "title": "YouTube"},
    "snapshot": "- textbox \"Search\" @e1",
    "key_elements": [{"ref": "@e1", "label": "textbox \"Search\""}]
  },
  "attachments": [
    {
      "id": "artifact-0123456789abcdef",
      "kind": "image",
      "mime_type": "image/png",
      "size": 248320,
      "sha256": "...",
      "encoding": "base64",
      "data": "...",
      "purpose": "browser_observation",
      "detail": "auto"
    }
  ]
}
```

Valid terminal statuses are `SUCCEEDED`, `FAILED`, `CANCELLED`, `EXPIRED`, `BLOCKED`, `WAITING_APPROVAL`, and `WAITING_USER`. An executor must report actual observed state and must not infer success from a dispatched command.

Observation attachments are transient evidence. Version 3 accepts at most two PNG/JPEG/WebP images of at most 4 MiB each, validates decoded size and SHA-256, and maps them to native multimodal model parts only when the active model declares `vision`, `multimodal`, or `image-input`. Attachment data is never stored in `agent_control_observation`, task history, logs, or frontend stream events; those surfaces receive metadata only.

### Progress

Long-running actions may emit non-terminal progress events before the final Observation. Runtime Client forwards these events to the active SSE stream and does not treat them as completion.

```json
{
  "protocol": "athena.agent.v3",
  "type": "PROGRESS",
  "task_id": "task-01",
  "action_id": "action-01",
  "session_id": "athena-00000000000000000000000000000000",
  "sequence": 1,
  "stage": "downloading",
  "message": "Downloading file: 12.4 MB",
  "progress": 42,
  "bytes": 13002342,
  "sent_at": "2026-08-03T10:00:08Z"
}
```

Progress events are best-effort UI feedback. They must not be used as model evidence unless followed by the terminal `OBSERVATION` generated by the Perception Layer.

### Task Session

The Runtime Client owns one correlated Task Session for each execution loop. It records ordering, active device sessions, actions, and observations. When the database is enabled, devices, tasks, actions, and observations are stored in `agent_control_*` tables and remain queryable after a service restart.

```json
{
  "task_id": "task-01",
  "conversation_id": "conversation-01",
  "user_id": "user-01",
  "device_id": "device-01",
  "status": "EVALUATING",
  "sequence": 2,
  "active_sessions": {"browser": "browser-01"},
  "actions": [],
  "observations": [],
  "created_at": "2026-08-03T10:00:00Z",
  "updated_at": "2026-08-03T10:00:05Z"
}
```

Task statuses are the closed set `UNDERSTANDING`, `PLANNING`, `WAITING_ACTION`, `WAITING_APPROVAL`, `EXECUTING`, `OBSERVING`, `EVALUATING`, `WAITING_USER`, `COMPLETED`, `FAILED`, and `CANCELLED`.

### Policy matrix

| Risk | Default decision | Examples |
| --- | --- | --- |
| `LOW` | `ALLOW` | Observe state, read an authorized file, scroll, take a screenshot |
| `MEDIUM` | `ALLOW` for reversible browser navigation; otherwise `ASK_USER` | Open a requested website, click a public search result, type a search query, open or close an application |
| `HIGH` | `ASK_USER` only through a purpose-specific capability | Send, purchase, book, modify an account, use credentials |

Generic keyboard, pointer, browser, and terminal capabilities must use `BLOCK` for consequential submissions. Opening a user-requested URL or application may be explicitly downgraded to `ALLOW`; this does not authorize subsequent interaction. `WAITING_USER` means the safe opening step completed and the device is waiting for manual login, CAPTCHA, QR, or 2FA work.

### Cancel

```json
{
  "protocol": "athena.agent.v3",
  "type": "CANCEL",
  "task_id": "task-01",
  "action_id": "action-01",
  "sequence": 1,
  "reason": "request canceled"
}
```

Authenticated control APIs are available for diagnostics and orchestration:

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/control/devices` | List online devices and advertised capabilities |
| `POST` | `/v1/control/devices/:device_id/bind` | Bind an online, unclaimed device to the authenticated user |
| `POST` | `/v1/control/actions` | Dispatch one action and wait for its observation |
| `GET` | `/v1/control/tasks?conversation_id=...` | List the authenticated user's durable Task Sessions |
| `GET` | `/v1/control/tasks/:task_id` | Inspect the correlated Task Session state |

## 中文说明

桌面端通过出站 WebSocket 连接 Runtime Client，因此本机不需要开放额外端口。Agent 只负责理解、规划和生成 Action；Launcher 只执行已声明的 Capability，并把真实环境状态作为 Observation 返回。

协议遵循固定分层：

- **Decision Layer（决策）**：决定下一步应该做什么。
- **Action Layer（执行）**：在设备上执行结构化 Action。
- **Perception Layer（感知）**：观察执行后的真实环境，并生成最终 Observation。

Browser Runtime、Desktop Runtime、File Runtime、Terminal Runtime 都属于执行适配器；Browser/Desktop/File/Terminal/Vision/Audio Observation Engine 都属于统一感知层。

- 每个 Action 都必须包含任务 ID、动作 ID、顺序号、幂等键和截止时间。
- 设备只执行自己在 `HELLO.capabilities` 中声明的能力。
- 重复的幂等键直接返回之前的 Observation，不重复操作电脑。
- 长时间 Action 可以在最终 Observation 前发送 `PROGRESS`；它只用于前端展示，不结束 Action，也不能替代 Perception Layer 生成的最终 Observation。
- 浏览器 Action 必须在同一个 `athena-*` session 内连续执行；每次 `browser.open`、`browser.action` 或 `browser.observe` 后都返回 URL、标题、页面快照和关键元素。
- HTTP 请求断开或超时后，服务端下发 `CANCEL`，桌面端取消对应 Context。
- `ASK_USER` 不会静默执行，设备返回 `WAITING_APPROVAL`；后续应由桌面审批界面恢复。
- 登录、验证码、扫码和 2FA 使用 `WAITING_USER`，用户完成后可在同一聊天中继续，Runtime Client 会恢复设备 Session。
- 截图附件只在当前 WebSocket 与模型回合中短暂存在，正文不会写入数据库、日志、任务历史或前端事件；不支持视觉的模型继续使用语义结构、标注图例和 OCR。
- 当前设备令牌是部署级共享密钥。远程多用户部署应在下一阶段替换为一次性配对码和设备级可撤销令牌。
- 开启数据库后，设备、Task Session、Action 和 Observation 会持久化；重复幂等键在服务重启后仍不会再次执行。
- 设备第一次被登录用户选中时会自动绑定，也可以调用绑定接口显式认领；绑定后其他用户无法查看或路由到该设备。
- 关闭前端 SSE 连接只会停止页面事件输出，不会取消后台任务。显式 Stop、Action deadline 或后台总超时仍会正常取消执行。
- 用户点击 Stop 时，Runtime Client 会按用户和会话查找待执行 Action，并通过同一 WebSocket 下发 `CANCEL`。

## Versioning Rule

`athena.agent.v3` is the current wire contract. It intentionally breaks v2 by adding bounded Observation attachments; Launcher, Runtime Client, and Agent Runtime must be upgraded together. New behavior still belongs in typed capabilities and the Action/Observation loop. Special assistant JSON, model-text action parsing, and frontend execution relays remain prohibited.
